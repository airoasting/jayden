# 회의록 작성 (Slack 복붙용)

Transcript를 읽고 **아젠다별로 논의사항 / 의사결정사항 / Next Step**을 정리한 회의록을 만든다. 결과물은 슬랙에 그대로 붙여넣을 plain text이다.

회의록의 독자는 회의에 참석하지 않은 사람 포함 모든 관련자이고, 핵심 용도는 "누가 무엇을 하기로 했는지"를 나중에 빠르게 확인하는 것이다. 그래서 대화의 흐름을 재현하기보다 **결론과 액션을 정확히** 남기는 데 집중한다.

## 작업 순서

1. **Transcript 전체를 먼저 읽고** 아젠다(주제 덩어리)를 파악한다. 발언 순서대로 요약하지 말고 주제별로 묶는다. 한 주제가 회의 중 여러 번 나뉘어 나와도 하나의 아젠다로 합친다.
2. **화자 → 소속 매핑.** Transcript는 보통 "참석자 1, 2, 3"처럼 익명이다. 대화 내용(발표자, 고객/수행사 관계, 호칭, 소속 언급)으로 소속을 추정해 `[소속]` 태그로 표기한다. 추정이 불확실하면 임의로 단정하지 말고 회의록 뒤에 "확인 필요" 한 줄로 알린다. 사용자가 이미 소속을 알려줬다면 그것을 따른다.
3. **STT 오류 보정.** 녹취 오탈자가 많다(예: "트래크/트래커" → 같은 툴, "땡" 등). 문맥상 명확한 고유명사·용어는 바로잡고, 확신이 없는 용어는 원문 그대로 두거나 "확인 필요"로 표시한다. 없는 내용을 지어내지 않는다.
4. 아래 출력 형식으로 작성하고 **코드블록 하나에 담아** 제공한다(슬랙에 붙일 때 서식이 깨지지 않도록). 코드블록 밖에는 짧은 확인 필요 사항만 덧붙인다.

## 출력 형식

```
YYMMDD {회의명} 회의록 - {파트/범위}

1. {아젠다 1}

논의사항

* [소속] 내용
   * [소속] 이어지는 응답/세부 내용

의사결정사항

* 확정된 내용

Next Step

* [담당 소속] 해야 할 일 (기한이 있으면 명시)


2. {아젠다 2}
...
```

- 제목 날짜는 사용자가 알려준 날짜/회의명을 쓴다. 모르면 비워두지 말고 사용자에게 한 줄로 물어보거나 `{날짜}`로 두고 알린다.
- 하위 아젠다가 있으면 `2-1.`, `2-2.` 식으로 번호를 붙인다.
- 슬랙은 `#` 헤더를 렌더링하지 않으므로 마크다운 헤더·표를 쓰지 않는다. 섹션 이름은 그냥 한 줄 텍스트로, 목록은 `* `로 쓰고 하위 항목은 3칸 들여쓴다.
- 논의사항·의사결정사항·Next Step 순서를 유지한다.

## 섹션별 기준

**논의사항** — 누가 어떤 입장/정보/요청을 말했는지를 `[소속]` 태그로 남긴다. 질문-응답은 들여쓰기로 묶는다. 잡담·인사·진행 멘트·반복 설명은 뺀다. 한 불릿은 1~2문장, 명사형/개조식("~함", "~필요", "~예정")으로 간결하게.

**의사결정사항** — "이렇게 하자"고 **실제로 합의되어 확정된 것만** 쓴다. 이 섹션의 신뢰도가 회의록 전체의 가치를 좌우하므로 보수적으로 판단한다.
- 포함: 일정·범위·방식이 명시적으로 합의/확정된 경우 ("11월 20일 전 배포로 간다", "이 방식으로 진행하자").
- 제외: 의견 제시, 검토하겠다는 약속, "~할 것 같다", "논의해보겠다", 미정이라 추후 정하기로 한 것, 한쪽만 말하고 상대 동의가 없는 것. 이런 것은 논의사항 또는 Next Step으로 보낸다.
- 해당 아젠다에 확정 사항이 없으면 **섹션 자체를 생략**한다(빈 섹션이나 "없음"을 억지로 채우지 않는다).

**Next Step** — 담당자(`[소속]`)와 행동이 분명한 후속 작업만. 논의사항에서 "~하겠다/확인해서 공유하겠다/검토 요청" 등으로 나온 약속을 빠짐없이 뽑는다. 기한이 언급되었으면 함께 적는다. 담당이 불분명하면 `[담당 미정]`으로 표기한다.

## 품질 체크

작성 후 스스로 점검한다.
- 의사결정사항에 "검토 예정/하겠다" 수준의 내용이 섞이지 않았는가?
- 논의사항에서 나온 약속이 Next Step에서 누락되지 않았는가?
- 같은 주제가 두 아젠다로 쪼개져 있지 않은가?
- Transcript에 없는 숫자·날짜·고유명사를 만들어내지 않았는가?

구체적인 톤과 밀도는 `references/example.md`의 예시를 참고한다(예시는 한 회의 중 AI 파트만 발췌한 것).
