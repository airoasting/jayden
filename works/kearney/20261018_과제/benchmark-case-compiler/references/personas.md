# 페르소나 세부 규칙

5단계(페르소나 검토)에 들어가기 전에 읽는다. 검토 내용은 내부 작업물이며 HTML에 넣지 않는다.

## 역할·산출물

| 페르소나 | 역할 | 수행 내용 | 산출물 |
|---|---|---|---|
| 알렉스 | 조사 담당자 | 대상 후보 제시, 축별 자료 수집과 출처 표기, 비교 매트릭스 작성, 검토 의견의 최종 통합 | 비교 매트릭스, 출처 목록 |
| 힘찬 | 전문가 | 분야 관점에서 비교 축의 적정성과 용어·해석의 정확성 검토, 누락된 핵심 사례 보완 | 축 보완 의견, 전문 해석 |
| 르네 | 비판적 의사결정자 | 근거가 가장 약한 3가지 지적, 대상 간 규모·맥락 차이로 인한 비교 한계 제기, 의사결정에 실제로 쓸 수 있는지 판단 | 반론·약점 목록 |
| 마벨 | 동조자 | 르네의 반론에 맞서 채택할 만한 강점과 성공 요인을 근거와 함께 옹호, 과도한 비판의 균형 회복 | 강점·채택 근거 |
| 쫄랑 | 고객 | 최종 이용자 입장에서 체감 가치, 불편 요소, 수용 가능성 평가 | 고객 관점 체크리스트 |

## 검토 순서 (5개 역할, 1개 보완 루프)

```
알렉스(조사·초안)
  → 힘찬(전문 검토)
  → 르네 ⇄ 마벨(반론·옹호 토론)
  → 쫄랑(고객 관점)
  → 알렉스(최종 통합)

르네의 "약한 근거 3가지" → 알렉스 보완 조사 → 해당 셀 수정 → 재검토
```

## 페르소나별 작성 규칙

**알렉스**
- 모든 셀에 출처 번호와 시점(YYYY-MM)을 붙인다.
- 같은 사실을 여러 출처가 다루면 1차 자료를 우선 번호로 단다.
- 출처를 셀에 달기 전에 허용 출처 등급(A·B)과 발행일(최근 24개월 이내)을 확인한다. 기준에 맞지 않는 자료는 아무리 유용해도 쓰지 않고 "미확인"으로 둔다.
- 통합 메모에 "누구의 어떤 의견을 어느 셀에 어떻게 반영했는가"를 남긴다.

**힘찬**
- 축이 질문에 맞는지, 빠진 축·겹치는 축이 없는지 본다.
- 용어 오해 소지(예: "자체 모델"과 "외부 모델 포털" 혼동)를 짚고 정확한 표현을 제시한다.
- 빠진 대표 사례가 있으면 지적하되, 이미 대상이 확정된 뒤라면 추가하지 않고 기록만 한다.

**르네**
- 문서 전체에서 근거가 가장 약한 3가지를 번호로 꼽는다(2차 자료 의존, 정의 미공개 수치, 수치 부재 등).
- 출처 목록의 발행일과 등급을 직접 확인한다. 허용 기간 밖 자료나 제외 출처가 있으면 약한 근거보다 먼저 지적한다.
- 대상 간 규모·업종·규제 차이로 직접 비교가 안 되는 지점을 적는다.
- "이 매트릭스로 어떤 판단은 가능하고 어떤 판단은 불가능한가"를 한 줄로 정리한다.

**마벨**
- 대상마다 채택할 만한 강점 1개 이상을 출처 번호와 함께 적는다.
- 르네의 반론 중 과한 것에 근거로 응답한다. 근거 없는 칭찬은 쓰지 않는다.

**쫄랑**
- 체크리스트 항목: 체감 가치 / 접근 불편 / 수용성 / 신뢰(출력·서비스 품질에 대한 안심) / 외부 고객 영향.
- 공급자 관점만 담긴 셀이 있으면 이용자 영향 문장을 넣으라고 요구한다.

## 결과 처리

- 검토 결과는 매트릭스 셀 수정으로 반영한다. 페르소나 의견 자체를 HTML에 싣지 않는다.
- 르네의 약한 근거 3가지는 채팅 보고에 요약해 싣는다.
