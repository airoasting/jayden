# 분석, 계산, 벤치마킹, 시사점

## 1. 주장의 구분

모든 주장을 아래 넷 중 하나로 표시한다.

| 구분 | 정의 | 예 |
|---|---|---|
| 사실 | 출처에서 확인한 내용 | "A사의 2023년 매출은 X (S-002, 3쪽 표 2)" |
| 해석 | 사실에서 도출한 판단 | "매출 증가는 신규 채널 효과로 보인다" |
| 가정 | 확인하지 못해 전제로 둔 내용 | "환율은 기준일 값을 유지한다고 가정" |
| 합성 예시 | 설명용 가상·교육용 수치 | "가상 기업 Z의 예시" |

가상 기업이나 교육용 수치를 실제 기업의 검증된 성과로 표현하지 않는다.

## 2. 계산 기록

- 사용한 데이터 범위, 필터, 분자·분모와 계산식을 남긴다.
- 집계 정의를 확인하지 않고 행별 비율을 단순 평균하지 않는다. 가중 평균이나 합계 기반 비율이 맞는지 먼저 확인한다.
- 계산을 수행하지 못했다면 검증 완료로 표현하지 않는다.
- 누락값을 0으로 바꾸지 않는다. 제외했다면 제외 건수와 이유를 적는다.

## 3. 벤치마킹

- 고객의 의사결정에 맞는 비교 축을 선택한다. 축을 고른 이유를 한 줄로 적는다.
- 정의·기간·단위·범위·분모가 다른 수치를 직접적인 성과 순위로 놓지 않는다.
- **비교 불가**(정의가 달라 비교할 수 없음)와 **미확인**(자료를 확인하지 못함)을 구분해 표시한다.

벤치마크 표 권장 열: 대상 / 비교 축 / 값 / 단위·기간·분모 / 근거 ID / 비교 가능 여부 / 한계.

## 4. 고객 시사점

- 관측 사실과 분리해서 쓴다.
- 각 시사점에 붙일 것: 근거 ID, 적용 조건, 대안 해석, 추가 확인 질문.
- 확인되지 않은 부분은 결론의 한계로 남기며, 필수 범위를 몰래 축소하지 않는다.

## 5. 정성 자료

정량 분석이나 벤치마킹이 요청 범위가 아니라면 해당 기능의 부재로 감점하지 않는다. 대신 정성 분석의 비교 논리와 적용 범위가 타당한지 평가받는다.
