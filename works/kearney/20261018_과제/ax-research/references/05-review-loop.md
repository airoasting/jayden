# 평가 → 수정 → 재평가

## 절차

1. **초안 고정.** Black이 검토할 결과에 버전(`v1`, `v2` …)을 붙이고 같은 내용을 모든 Red에 전달한다. 대화 속 초안도 버전과 전체 검토 내용을 고정하면 된다. 파일 해시나 별도 저장 도구는 필수가 아니다.
2. **평가 수집.** 모든 Red의 해당 버전 평가를 받는다. Black은 점수 범위·합계·누락·버전 일치를 확인한다. 유효하지 않은 평가는 다시 받아야 하며 임의로 점수를 채우거나 해당 리뷰어를 평균에서 제외하지 않는다.
3. **통과 판정.** 다음 조건을 모두 만족해야 통과한다.
   - 등록한 Red 전원이 동일한 최신 버전을 평가했다.
   - `평균 = Red 점수 합계 ÷ Red 수`가 **반올림 전 값으로 9.5/10 이상**이다. 소수 첫째 자리 점수를 정수 단위(×10)로 환산해 합계와 기준을 비교하면 반올림 오판을 피할 수 있다. `scripts/check_pass.py`가 이 계산을 수행한다.
   - 미해결 차단·중대 지적이 없고 사용자가 요청한 필수 범위와 검증을 충족했다.
4. **수정.** Black은 지적별 수정 내용과 근거를 `templates/revision-log.md`에 기록한다. 동의하지 않는 지적도 근거를 제시하고 해당 Red가 재확인하도록 한다. Black이 Red의 점수나 판정을 대신 바꾸지 않는다.
5. **재평가.** 수정한 버전을 모든 Red가 다시 평가한다. 지적과 수정 근거는 전달하되 가능하면 새 검토 컨텍스트를 사용하고 이전 점수는 전달하지 않는다. 변경한 부분뿐 아니라 결과 전체에 새로운 문제가 없는지도 확인한다.
6. 통과하거나 아래 중단 조건에 해당할 때까지 반복한다. 최신 라운드 전원의 점수만 사용하고 과거 점수와 섞지 않는다. 통과 후 내용을 바꾸면 기존 판정을 재사용하지 않는다.

## 점수 관련 원칙

- 미달 점수에 실행 가능한 지적이 없다면 Red가 감점 이유와 필요한 보완을 구체화하도록 한다.
- 채점 오류는 같은 기준으로 다시 평가하고 정정 이유를 남긴다.
- 목표 점수에 맞추기 위해 문제를 만들어내거나 점수를 올리지 않는다.
- 라운드 중 리뷰어·기준·가중치를 바꿔 통과시키지 않는다. 실제 범위 변경이나 리뷰어 교체가 필요하면 이유를 기록하고 해당 버전에 대한 전원 평가를 새로 시작한다. 이미 사용한 라운드는 초기화하지 않는다.

## 중단 조건

- 기본 최대 **5라운드**(최초 평가 1회 + 최대 4회 수정·재평가). 사용자가 다른 한도를 정하면 따른다. 한도에 도달해도 9.5점 기준을 낮추지 않는다.
- 필수 자료·접근·도구 또는 사람의 판단 없이는 진행할 수 없으면 **추가 입력 필요**로 종료하고 무엇이 필요한지 구체적으로 적는다. 해결 가능한 문제는 먼저 수정한다.
- 한도까지 유효한 통과 판정을 얻지 못하면 **기준 미달**로 종료하고 현재 결과·점수·미해결 사항을 제공한다. 실제 원인이 입력 부족이면 **추가 입력 필요**로 구분한다. 통과하지 않은 결과를 완성본으로 표현하지 않는다.

## 종료 상태 판단

| 상황 | 종료 상태 |
|---|---|
| 조건 3개 충족 | 통과 |
| 필수 자료·접근·판단이 없어 진행 불가 | 추가 입력 필요 |
| 한도까지 통과 못 함, 원인이 품질 | 기준 미달 |
| 한도까지 통과 못 함, 원인이 입력 부족 | 추가 입력 필요 |
