# 최종 전달

## 형식

사용자가 정한 형식으로 결과를 제공한다. 형식이 없으면 아래 네 부분을 기본으로 대화에 작성한다. 양식은 `templates/final-report.md`.

1. **핵심 결론.** 조사 질문에 대한 답과 적용 조건. 미통과 결과라면 잠정 결과임을 표시한다.
2. **근거와 비교.** 출처 목록, 근거 ID별 주장·원문 위치·계산·한계, 필요한 경우 벤치마크 표.
3. **시사점과 남은 질문.** 근거에 연결된 해석, 미확인 항목과 다음 확인 사항.
4. **검토 요약.** 통과 / 추가 입력 필요 / 기준 미달, 실제 검토 방식, 최종 버전, 라운드별 리뷰어 점수와 평균, 주요 수정, 남은 지적과 종료 이유.

## 저장

파일 저장은 요청되었거나 기존 작업 범위에 포함된 경우에만 수행한다. 고정 폴더나 파일명을 요구하지 않는다. 저장할 때는 기본으로 `results/<YYYY-MM-DD>-<주제-슬러그>/` 폴더를 만들어 사용한다. 사용자가 다른 위치를 지정하면 그곳을 따른다. 자세한 구조는 `results/README.md`.

## 검토 요약 작성 규칙

- 최종 평균의 합계·리뷰어 수를 남겨 통과 여부를 재확인할 수 있게 한다. (예: `합계 28.6 ÷ 3 = 9.53`)
- 실제 검토 방식을 정직하게 적는다: "별도 Subagent 3명" 또는 "동일 Agent의 페르소나별 자기 검토".
- 상세 리뷰 기록은 현재 작업 안에 유지하며, 최종 답변에서는 핵심 지적과 조치만 간결히 전달한다.
- 통과하지 못했으면 완성본처럼 쓰지 않는다.
